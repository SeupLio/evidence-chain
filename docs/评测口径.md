# 评测口径说明

> 面向评委与工程复核：这个系统如何证明「准」，以及哪些地方**不准**。

---

## 1. 为什么不自建金标

上一版用「脚本生成年报 + 生成方持有金标」的方式评测，指标是 100%。
问题不在于数字真假，而在于**出题人和答题人是同一个**：

- 合成语料的版式由我们决定，抽取器的规则也由我们决定；
- 金标由同一个脚本写出，抽取器的盲区不会出现在金标里；
- 100% 只能说明「在自家模板上没退化」，不能说明「在真实年报上可用」。

本版把评测拆成两条互不替代的赛道：

| 赛道 | 输入 | 参照 | 用途 | 是否对外称「精度」 |
|---|---|---|---|---|
| 跨源互证 | 巨潮年报 PDF | 东方财富结构化数据 | 真实能力 | **是** |
| 模板回归 | 合成年报 PDF | 生成方金标 | 防退化 | 否 |

两条赛道用 `documents.dataset_tag` 隔离：

- `real_cninfo`：真实公开年报与派生事实；跨源互证只读这一层；
- `synthetic_regression`：仅用于抽取器回归的合成 PDF；模板回归、冲突注入、增量隔离只读这一层；
- `demo_controlled`：明确标注「非真实披露」的演练更正公告，只用于演示补证流程。

真实库不允许混入合成语料：`seed_corpus()` 检测到 `real_cninfo` 文档会直接返回
`DATASET_CONFLICT`。评测页在需要时会启动**独立临时 `DATA_DIR` 的子进程**运行回归赛道，
结果回传但不写入主库。

## 2. 数据来源与抽样

- **年报原件**：巨潮资讯（交易所指定披露平台）年度报告正文，54 份（6 行业 × 3 家 × 2023–2025）。
  同一年的 A 股版与 H 股版同时命中时，只取披露最早的 A 股正文。
- **第三方数据**：东方财富 F10 年报口径接口（利润表 / 资产负债表 / 现金流量表），
  18 家 × 30 年 × 10 字段，落库时保留 `source_url`、`fetched_at`、`source_field`。
- **样本选择**：每个行业固定三家（龙头 / 次龙头 / 差异化），不做「挑好抽的」筛选。
  2023 年以前的年报也下载了部分，但不参与本轮比对。

## 3. 比对规则

对每个 `(公司, 字段, 财年)`：

1. 取 PDF 抽取的**合并口径**值（母公司口径不参与）；
2. 取第三方同财年值；
3. 按顺序判定：

| 判定 | 条件 | 含义 |
|---|---|---|
| `exact` | 差值为 0 | 完全一致 |
| `rounding` | 差值 ≤ 1 元，或相对差 ≤ 0.002% | 对方按元四舍五入 |
| `unit` | 比值接近 1000 / 10000 / 10⁶ / 10⁸ | 单位换算错（真实缺陷，单独计数） |
| `mismatch` | 其余 | 需要人工看 |

一致率 = `(exact + rounding) / 可比值`。**`unit` 不算一致**，哪怕它「只差一个数量级」。

两边只有一边有值时不计入分母，但单独统计「原件缺」（`miss_pdf`）——
覆盖率本身也是结论的一部分。

## 5. 失败归因

不一致样本不做删改，按原因归为五类（评测页逐条列出公司、字段、页码、两边数值）：

| 类型 | 典型表现 | 根因 | 是否可修 |
|---|---|---|---|
| 列错位 | 抽到母公司列，数值约为合并口径的 20%–50% | 表头无「合并/母公司」字样时默认合并 | 可修：用报表标题与列数推断 |
| 年份错位 | 2023 报表的 2022 列被记成 2023 | 表头与数字的锚点偏移 | 已修大部分，仍有残留 |
| 行混淆 | 经营现金流取到「将净利润调节为经营现金流」 | 补充资料与主表同名行 | 可修：限定报表区块 |
| 标签拆行 | 「归属于母公司股东的净利润」被拆成两行 | PDF 文本层断行 | 部分已修（括号闭合判断） |
| 口径差异 | 营业总收入 vs 营业收入 | 准则允许两种列报 | 需人工确认，不强行统一 |

**为什么保留这些失败**：它们恰好是真实年报里最容易出错的地方。
把 84.1% 换成 100%，只能靠删样本或放宽规则，那评测就失去了意义。

---

## 6. 不适用的比较

- **样本合计 ≠ 行业总量**：三家公司加总不能代表行业规模，报告里一律写「样本口径（n=3）」。
- **跨行业比毛利率**：商业模式不同（白酒 70%+、汽车 15%），只能比趋势，不能排名。
- **资产负债率**：分子是总负债，不是有息债务，不能当作偿债能力结论。
- **n<2 不输出基准**：只有一家可比公司时，中位数没有意义。

## 7. 如何复现

```bash
cd backend
../.venv/Scripts/python.exe -m app.scripts.build_real --years 2023 2024 2025   # 拉数据（首次约 2 分钟）
../.venv/Scripts/python.exe -m app.cli eval                                   # 打印两条赛道 JSON
```

或打开 `http://127.0.0.1:8000/#eval`，页面上的「重新运行」会重新计算并展示失败样本。
回归赛道若不在当前库，会在独立临时 `DATA_DIR` 启动子进程运行，主库不会被写入。

单独复现回归赛道：

```bash
# PowerShell
$env:DATA_DIR="data/regression"; python -m app.cli seed --pack beer-demo; python -m app.cli run; python -m app.cli eval
```

评测代码：`app/eval/crosscheck.py`（比对规则）、`app/eval/harness.py`（汇总）、
`app/eval/regression.py`（隔离执行器）。

## 8. 局限

1. 参照值本身也可能错。第三方数据存在录入错误与口径调整，因此「不一致」不等于「我方错」，
   `mismatch` 需要人工看页码确认。
2. 只覆盖 6 个行业、9 个字段。金融业（银行/保险）报表结构完全不同，未纳入。
3. 只处理有文本层的 PDF。扫描件、图片型年报会标 `SCANNED_UNSUPPORTED`，不做 OCR。
4. 跨年重述的判定依赖「同一指标出现在两份年报里」。只披露一期的公司无法检测。
5. 一致率会随样本变化。增加行业或年份后必须重新跑，不允许沿用旧数字。

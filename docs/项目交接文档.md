## 1. 项目背景

### 1.1 比赛与命题背景

本项目用于参加由中国人民大学承办、中国工商银行提供企业命题的黑客松比赛，对应**企业命题二：AI 驱动的行业研究与企业经营分析助手**。

命题要求设计一个由多个 AI 智能体分工协作的分析助手，完成：

- 从公开资料中搜集材料；
- 核验信息、标记来源、时间与矛盾；
- 分析企业经营状况并进行同业/行业比较；
- 识别经营或财务风险并说明判断依据；
- 生成能说明数据出处的报告；
- 支持用户追问与资料更新后的增量修订。

初赛评分共 100 分：

| 评分项 | 分值 | 本项目的核心回应 |
|---|---:|---|
| 赛道契合与问题判断 | 25 | 产品首页先讲清“谁在用、解决什么问题”，四层证据链对应“结论凭什么” |
| 功能与完成度 | 40 | 6 行业 / 18 家公司 / 54 份年报真实可跑，五个页面均为真实数据 |
| 应用价值与可验证性 | 25 | 原件可点回、跨源互证公开失败样本、评测可复跑 |
| 视频表达 | 10 | `docs/演示脚本_1分钟.md` 已给出 6 分镜与逐秒口播 |

### 1.2 用户与痛点

目标用户是券商研究员、银行行业研究员、投研助理、企业战略分析人员。核心痛点不是“缺少文本生成能力”，而是**结论无法回溯到原始证据**：

| 真实痛点 | 系统对应设计 |
|---|---|
| 同一指标散落在管理层讨论、三张主表、附注与更正公告里 | 按“年份 + 合并/母公司 + 主表/附注”定位，附注排除并留痕 |
| 合并/母公司、万元/元、期末/期初容易混用 | 口径写入 `FactKey`，单位换算单独记录，错位给出 `SCOPE_MISMATCH` |
| 报告常常只有观点，没有页码和单元格 | 四层证据链：指标 → 算式 → 单元格 → 原件 |
| 新增一期年报后，整篇报告被重写，旧版本不可比 | 依赖图 + 章节内容指纹，只改受影响章节 |
| 传统评测用自造语料与自造金标，存在“自己出题自己答” | 主评测改为巨潮原件 vs 东方财富结构化数据跨源互证 |

### 1.3 产品定位

系统不是“自动写研报的聊天框”，而是一张**可复核、可更新、可审计的企业研究底稿**。一句话表达：

> 每个数字能点回原表的某一格，每条结论有引用与反证，每次新增一期年报只改受影响的部分。

视觉上采用近黑底 + 荧光青柠（行动）+ 香槟金（证据），并用**人大红 / 工行红**作为关键点缀，避免大面积滥用红色。该调整来自用户提供的 `项目修改清单.md`，目的是让项目呈现“给人用的产品”，而非后端函数与按钮集合。

## 3. 技术路线

### 3.1 总体架构

```text
浏览器（React 18 + TypeScript + ECharts）
   │  REST + SSE（Last-Event-ID 续传，(run_id, seq) 幂等）
FastAPI / uvicorn 单 worker
   │  进程内单任务队列，任务内解析与检索并发
   ├─ plan ─ collect ─ ingest ─┬─ finance_extract ─ verify_calc ─┐
   │                           └─ industry ─ validate_industry ─┤
   │                                                             ▼
   └─────────────── build_ctx → risk_explain → compose → audit → publish
   │
SQLite（WAL、短事务）+ 按 SHA-256 寻址的原件目录 + 前端构建产物同源托管
```

关键取舍：

- **图只调度**：工作流状态只保存引用、状态与问题，业务真值留在服务端对象里；
- **两支并行互不遮蔽**：财务核验与行业图谱可并行，单支失败只标本支状态，最终报告可为 `partial`；
- **单进程单任务**：不引入 Redis / Celery，减少现场部署故障点；
- **不用 LangGraph**：仅需命名节点、并行、join、reducer 与 SSE 事件，自写约 130 行执行器足够。详见 `docs/ADR-0001-workflow-engine.md`。

### 3.2 数据层路线

#### 3.2.1 第三方结构化数据

`backend/app/services/market.py` 拉取东方财富 F10 接口：

- `RPT_F10_FINANCE_GINCOME`
- `RPT_F10_FINANCE_GBALANCE`
- `RPT_F10_FINANCE_GCASHFLOW`

落库时保留 `source_url`、`fetched_at`、`source_field`，支持 `live / cached / replay` 三种模式。缓存文件位于 `data/cache/`，`--mode replay` 可在断网情况下演示。

#### 3.2.2 年报原件

`backend/app/services/filings.py` 从巨潮资讯检索并下载公告 PDF。关键修复是 `orgId` 不能按固定规则猜测，必须从官方全量 `szse_stock.json` 查询；该缓存文件位于 `data/cache/szse_stock.json`。

#### 3.2.3 真实 PDF 抽取

`backend/app/services/pdf_lines.py` 是真实年报链路的核心，重点处理：

- `pdfplumber` 文本与表格坐标，按 y 坐标聚行；
- 表头在上一页时的跨页继承；
- 数字右对齐、行名拆行、括号全半角差异；
- 合并 / 母公司表头并列与口径隔离；
- 期初列 `2025年1月1日` 映射到 `2024-12-31`；
- 同名行在附注与主表重复时优先采信主表；
- bbox 按页相对坐标输出，前端按百分比定位，兼容缩放与高 DPI。

抽取结果为 `ParseResult`，再经 `real_ingest.py` 入库为 `facts`、`source_locations`、`documents`。

### 3.3 业务语义层路线

#### 3.3.1 FactKey：口径即身份

```text
entity_id | field_code | period_start~period_end | period_kind
          | consolidation | currency | business_scope | definition_id
```

- 期末余额用 `POINT`，流量用 `FY`；
- `period_end` 相同但起始日不同绝不合并；
- 合并利润表收入与业务分部收入是两条不同键；
- `raw_value` 永久保留，换算值单独存储；
- 破折号、空白、无意义文本不默认为 0。

#### 3.3.2 稳定标识与数值

| 对象 | 派生方式 |
|---|---|
| 事实版本 ID | SHA-256(事实键 + 文档 ID + 文档 sha256 + 锚点 + 原始值 + basis) |
| 指标结果 ID | SHA-256(指标键 + 公式版本 + 输入版本 ID + 状态 + 值) |
| Claim 版本 ID | SHA-256(claim_key + 模板 + slots + 引用 + 文本 + 审核结论) |
| 报告指纹 | SHA-256(解析器/抽取器版本 + 模型配置 + prompt 版本 + 规则版本 + 证据集 + as_of + 工作流版本) |

金额与比率全程 `Decimal(prec=34)`，比例按小数存储（50% 存 `0.5`），展示时 `ROUND_HALF_UP` 保留两位；`pp` 指标已乘 100，前端不再换算。

#### 3.3.3 核验与勾稽

核验顺序：数值预处理 → 口径分桶 → 舍入相容 → 权威选择 → 决策 → 勾稽检查。

权威层级从高到低为：正式更正（100）→ 原始审计年报主表（86）→ 年报摘要表（80）→ 其他同口径正式披露（70）→ 二手来源（10）。更正公告中的“更正前”列视为被替代值（55）。

勾稽检查包括：

- 资产总计 = 负债合计 + 所有者权益合计；
- 净利润 = 归母净利润 + 少数股东损益；
- 负债和所有者权益总计 = 资产总计；
- 分部收入/成本合计 = 合并总额。

输入不全记 `NOT_CHECKED`，不声称“已通过”。

### 3.4 分析与风险路线

9 个白名单公式：`revenue_yoy`、`gross_margin`、`parent_net_margin`、`debt_asset_ratio`、`ocf_margin`、`cash_conversion` 及三个 `*_delta_pp` 指标。

4 条风险规则：

| 规则 | 触发逻辑 | 输出要求 |
|---|---|---|
| `margin_pressure` | 毛利率同比 ≤ −2pp；低于同业中位数 3pp 时增强 | 必须给观察事实 / 阈值 / 潜在影响 / 反证与下一份材料 |
| `cash_divergence` | 净利润 > 0 且 OCF < 0；或营收增长但 OCF/营收下降 ≥ 5pp | 同上 |
| `balance_sheet_watch` | 资产负债率同比升 ≥ 5pp 且绝对值 ≥ 65% | 标记需人工核对，不作授信结论 |
| `evidence_integrity` | 关键字段存在 BLOCKING 问题、披露日不可靠或勾稽未通过 | 标记需人工核对 |

规则是确定性函数，模型只能解释、不能改判、不能设阈值、不能报违约概率。未触发时只能说“本次覆盖规则未触发”，并列出未评估项，不写“公司无风险”。

### 3.5 报告、引用与更新路线

#### 3.5.1 Claim 与数字守卫

- 8 个固定章节：`overview / industry / operations / financials / peer / risk / chain / data_quality`；
- Claim 五类：`fact / calculation / interpretation / hypothesis / unknown`；
- 模板中不允许出现阿拉伯数字，数字只能通过 `{{m:...}}`、`{{f:...}}` 等槽位注入；
- 渲染后检查字符区间，区间外出现数字即 `CLAIM_UNBOUND_NUMBER` → BLOCK；
- 强断言词（必然 / 证实 / 造假 / 违约）BLOCK，因果词 WARN 转人工复核。

#### 3.5.2 四层证据链

1. 数值与口径：`metric_results`；
2. 算式与代值：`FORMULAS` + `metric.inputs`；
3. 原文：`pypdfium2` 页面 PNG + bbox 红框 + 摘录；
4. 原件：标题、主体、披露日、抓取日、SHA-256、解析器版本。

#### 3.5.3 增量更新

依赖图为 `fact → metric → rule → claim → section → 摘要`，并设置 `coverage / peer_set / topic` 哨兵捕获新事实。

流程：

```text
changed  = diff(old_resolutions, new_resolutions) + 新增事实键
impacted = downstream_bfs(union(old_deps, new_deps), changed)
recompute affected metrics / peer groups → rerun rules & claims
copy untouched section_version_ids → 只重新渲染命中章节
validate all refs → old/new/diff/recompute 计划
commit: CAS 更新 head；基线过期 → 409 STALE_BASE；无语义变更 → NO_CHANGE
```

历史合成基线实测：变化 2 条事实、2 条指标，预测影响 6 章，实际改写 6 章，未命中 2 章保持同一 `section_version_id`，旧版本完整可读。

### 3.6 模型通道

`backend/app/providers/llm.py` 提供 OpenAI 兼容接口，环境变量为 `LLM_BASE_URL / LLM_MODEL / LLM_API_KEY`。当前未配置密钥，`model_mode=live` 尚未经过真实模型验收；默认走确定性 `mock / replay`，界面会明确标注模型状态。

1. 不越出当前 `report_version` 的证据范围；
2. 不写出数字守卫之外的任何数字。

## 7. 已知问题与风险

### 7.1 评测环境隔离问题（最高优先级）

当前 `crosscheck.py::pdf_facts()` 只按 `entity_id + field_code + period_end + consolidation` 查 `facts`，**没有按文档来源过滤**。因此在真实数据库上执行 `seed --pack beer-demo` 后，合成年报的事实会混入比对池。

本机实测：

| 场景 | 可比值 | 一致率 |
|---|---:|---:|
| 当前干净真实数据库 | 384 | 84.11% |
| 同一数据库追加合成语料后 | 409 | 69.68% |

后者不是真实能力下降，而是合成事实污染了真实口径。修复方向：

1. 在 `documents` 上明确 `source_type` / `dataset_tag`（`real_cninfo` vs `synthetic_regression`）；
2. `crosscheck.pdf_facts()` 只查 `real_cninfo`；
3. `extraction_scores()` / `conflict_scores()` / `incremental_scores()` 只查 `synthetic_regression`；
4. 两套赛道使用独立 `DATA_DIR`，或至少在评测入口强制切换上下文；
5. 更新 `start.sh`，比赛演示默认不导入合成语料。

### 7.2 完整评测项的当前状态

在**当前真实-only 数据库**上直接运行 `app.cli eval`：

- 模板回归 `template_track` 显示 `0/192`，因为合成语料未导入；
- 增量隔离返回 `{"error": "语料缺少更正公告"}`，因为真实语料没有 `correction` 文档；
- 引用可达为 21/21；
- 冲突判别为 1/2 通过。

在**数据库副本上追加合成语料**后：

- 模板回归恢复为 192/192；
- 增量隔离可运行，但因为事实池混合，测得 `impact_exact=false`，不能作为有效结论；
- 跨源互证被污染至 69.68%。

因此，对外表述应坚持：**当前可对外引用的真实精度口径是干净真实库上的 84.1%**；模板回归与增量隔离属于回归赛道，需在隔离环境复现后再引用。

### 7.3 冲突判别剩余失败

冲突判别中 `unannounced_restatement` 用例期望 `BLOCKED`，实际为 `AGREED`。这说明“同一字段存在未公告的不同版本值”尚未被稳定判为冲突。建议检查 `verify.py` 的权威排序与 `resolution` 生成逻辑，确保当两份同级正式披露数值不同且无正式更正关系时，不因排序取第一而降级为 `AGREED`。

### 7.4 抽取器真实误差

约 16% 的跨源不一致仍真实存在，失败类型包括：

- 列错位（母公司列被当合并）；
- 年份错位（表头与数字锚点偏移）；
- 行混淆（补充资料同名行）；
- 标签拆行（文本层断行）；
- 口径差异（营业总收入 vs 营业收入）。

失败样本已公开在评测页，不应通过删样本、放宽容差或改参照值把数字“修”到 100%。优先改进顺序建议：存货 → 营业成本 → 营业收入 → 经营现金流 → 汽车行业。

### 7.5 其他边界

| 项 | 状态 | 说明 |
|---|---|---|
| 扫描件 OCR | 不支持 | 无文本层标 `SCANNED_UNSUPPORTED`，允许人工录入候选 |
| 任意用户上传 | 不支持 | 只处理预置语料与受控候选 |
| Neo4j / 向量库 | 未使用 | 产业链为结构化边表，检索用 SQLite |
| 实时行情 / 信用评分 | 不做 | 只输出观察线索，不输出投资或授信结论 |
| 鉴权与多租户 | 未做 | 仅本机监听；上线需 SSO、最小权限、审计留存、内外网隔离 |
| 进程重启恢复 | 未做 | stale running 标 interrupted，重试建新 run 并复用工件 |
| 真实 LLM 通道 | 接口已留，未验收 | 需密钥；接入后必须重跑数字守卫与版本边界测试 |
| 文档数字一致性 | 部分滞后 | README/实施说明中的“23 条引用”“冲突通过数”等与当前复核略有出入，交接后应统一刷新 |

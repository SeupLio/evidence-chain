## 1. 文档目的

本文说明三件事：

1. 计划书里的每个技术环节**实现成了什么**（可运行代码 + 可复核产物）；

## 3. 系统架构

```
浏览器（React 18 + TS + ECharts）
   │ REST + SSE（断线按 Last-Event-ID 续传，事件按 (run_id,seq) 幂等）
FastAPI（uvicorn 单 worker）+ 进程内单并发任务队列
   │
   ├─ plan ─ collect ─ ingest ─┬─ finance_extract ─ verify_calc ─┐
   │                           └─ industry ─ validate_industry ──┤
   │                                                             ▼
   └─────────────── build_ctx → risk_explain → compose → audit → publish
   │
SQLite（WAL，短事务）+ 内容寻址的原件目录（按 SHA-256）
```

**关键取舍**

- **图只调度**：图状态只放 `ref / statuses / issues`，业务真值在服务端对象里；
  不使用「让图保存报告」的做法。
- **两支并行且互不遮蔽**：单支失败只标 `statuses[node]=fail`，另一支照常完成，
  最终报告可为 `partial`。
- **单进程单任务**：不引入 Redis/Celery。解析与检索在任务内部并发。

实现说明见 `docs/ADR-0001-workflow-engine.md`（为何不用 LangGraph）。

## 4. 数据契约要点

### 4.1 FactKey（口径即身份）

```
entity_id | field_code | period_start~period_end | period_kind | consolidation
          | currency  | business_scope           | definition_id
```

- 币种与定义属于键：不同就不是同一个事实；
- 期末余额 `POINT`，流量 `FY`；`period_end` 相同但起始日不同者**绝不合并**；
- 例：合并利润表「营业收入」与啤酒业务分部收入是两条键；
  「亿元保留两位」与「元」是同一键的不同展示单位。

### 4.2 稳定标识

| 对象 | 派生方式 |
|---|---|
| 事实版本 ID | SHA-256(事实键 + 文档 ID + 文档 sha256 + 锚点 + 原始值 + basis) |
| 指标结果 ID | SHA-256(指标键 + 公式版本 + 输入版本 ID + 状态 + 值) |
| 结论版本 ID | SHA-256(claim_key + 模板 + slots + 引用 + 文本 + 审核结论) |
| 报告指纹 | SHA-256(解析器/抽取器版本 + 模型配置 + prompt 版本 + 规则版本 + 证据集 + as_of + 工作流版本) |

`as_of` 是可见信息截止：晚于截止日的文档不参与该次运行；发布日不明的财务证据不进主指标。

### 4.3 数值

金额与比率全程 `Decimal` + `localcontext(prec=34)`；比例存储（50% 存 `0.5`），
展示 2 位 `ROUND_HALF_UP`；`pp` 指标已乘 100，前端不再换算。
`raw_value` 永久保留，单位换算后的数值独立存储。
破折号、空白、无意义文本**不默认为 0**。

## 5. 证据链四层

点击任意数字，抽屉按四层展开：

| 层 | 内容 | 数据来源 |
|---|---|---|
| ① 数值与口径 | 值 + 实体/财年/比较范围/置信度徽章 | `metric_results` |
| ② 算式与代值 | 公式文本、变量名、读取值、页码·单元格，逐行可点继续下钻 | `FORMULAS` + `metric.inputs` |
| ③ 原文 | 原页 PNG + 归一化 bbox 红框 + 原文摘录 | `pypdfium2` 渲染 + `source_locations.bbox` |
| ④ 原件 | 标题、发布主体、类型、披露日、抓取日、sha256、解析器版本 | `documents` |

「采信理由」由核验引擎给出（例如「采信 XX 年报（primary_table，元）；2 份候选在舍入区间内一致（最大差 17.35 元）」），
不是模型措辞。

> 实现细节：bbox 为页相对坐标（左上原点，不乘设备像素率），
> 前端按图片尺寸百分比定位，缩放与 2x 屏下均对齐；旋转/非默认裁剪页禁用高亮、只跳页。

## 6. 核验引擎判定策略

顺序：**数值预处理 → 口径分桶 → 舍入相容 → 权威选择 → 决策 → 勾稽检查**。

### 6.1 决策表

| 决策 | 触发条件 | 指标后果 |
|---|---|---|
| `AGREED` | 同键候选在舍入容差内一致 | 正常计算 |
| `ROUNDING_COMPATIBLE`（问题码，非决策） | `|a−b| ≤ (step_a + step_b)/2` | 视为一致，记 INFO |
| `SUPERSEDED` | 正式更正明确替代原披露 | 采信更正后值，新旧都可读 |
| `ACCEPTED_WITH_CONFLICT` | 有明确优先证据但仍冲突 | 采信优先者，保留两值与引文 |
| `BLOCKED` | 同级冲突且无法判定 | **冻结该事实与依赖指标** |
| `PROVISIONAL` | 仅二手来源 / 抽取置信不足 | 核心表只显示缺证 |
| `MISSING` | 无候选 | 指标 `MISSING_INPUT` |

### 6.2 权威层级

```
正式更正（restated） 100
原始审计年报 主表      86
年度报告 摘要表        80
其他同口径正式披露     70
二手来源（研报/媒体）  10
```

更正公告里的「更正前」列视为**被替代值**（55），低于年报原表——它不是可采信来源。

### 6.3 勾稽检查

| 检查 | 容差 | 未通过后果 |
|---|---|---|
| 资产总计 = 负债合计 + 所有者权益合计 | 1 元 | `RECONCILE_FAIL`，冻结依赖指标 |
| 净利润 = 归母净利润 + 少数股东损益 | 1 元 | 同上 |
| 负债和所有者权益总计 = 资产总计 | 1 元 | 同上 |
| 分部收入/成本合计 = 合并总额 | 1 元 | 拒绝执行毛利率结构分解 |

输入不全记 `NOT_CHECKED`，**不声称已通过**。

## 7. 指标与公式

| 指标 | 算式 | 单位 | 缺证与边界 |
|---|---|---|---|
| revenue_yoy | `revenue_t / revenue_t1 − 1` | fraction | 基数须正；缺上期 → `NO_BASE` |
| gross_margin | `(revenue − operating_cost) / revenue` | fraction | 正收入 |
| parent_net_margin | `net_profit_parent / revenue` | fraction | 归母净利率，不当作合并净利率 |
| debt_asset_ratio | `total_liabilities / total_assets` | fraction | 分子为总负债，非有息债务 |
| ocf_margin | `operating_cashflow / revenue` | fraction | 允许 OCF 为负 |
| cash_conversion | `operating_cashflow / net_profit_total` | fraction | 分母 ≤ 0 时不出比例，只给原值 |
| gross_margin_delta_pp | `(gm_t − gm_t1) × 100` | pp | 符号保留 |
| asset_ratio_delta_pp | `(dar_t − dar_t1) × 100` | pp | 需同口径两期期末 |
| ocf_margin_delta_pp | `(ocfm_t − ocfm_t1) × 100` | pp | 供现金流规则使用 |

**独立复算**：评测用 `fractions.Fraction` 另写一遍公式，不复用生产函数，
避免「同一函数算两遍」的假一致。实测 108/108 一致（干净基线）。

**分部毛利率变动恒等分解**（P1）：

```
Δ = Σ(w₁ − w₀)·m₀   （结构项）
  + Σ w₁·(m₁ − m₀)  （分部毛利率项）
  + 残差
```

仅在分部四项齐全、分部合计与合并总额勾稽通过、残差 ≤ 0.05pp 时输出；
实测结构项 −0.03pp、分部毛利率项 −2.54pp、残差 0.000pp——
结论是「变动来自分部毛利率本身，而非收入结构迁移」，这是对「高端化导致结构升级」说法的反证。

## 8. 风险规则（v1 演示配置）

| 规则 | 触发条件 | 输出 |
|---|---|---|
| margin_pressure | 毛利率同比 ≤ −2pp；若同时低于可比同行中位数 3pp 标「增强」 | 关注 |
| cash_divergence | 净利润 > 0 且 OCF < 0；或营收同比 > 0 且 OCF/营收同比降 ≥ 5pp | 关注 |
| balance_sheet_watch | 资产负债率同比升 ≥ 5pp 且绝对值 ≥ 65% | 需人工核对 |
| evidence_integrity | 关键字段存在 BLOCKING 级数据质量问题、披露日不可靠或勾稽未通过 | 需人工核对 |

规则是确定性函数，只吃指标快照 + 同业基准，输出 `TRIGGERED / NOT_TRIGGERED / NOT_EVALUABLE`。
模型只能解释，不能改判、不能设阈值、不能报违约概率。

每条触发规则必须给出四段：**观察事实 / 阈值 / 潜在影响 / 反证与下一份材料**。
未触发时只能说「本次覆盖规则未触发」，同时列出未评估项——**不写「公司无风险」**。

## 9. 报告、Claim 与引用守卫

- 固定 8 个章节：overview / industry / operations / financials / peer / risk / chain / data_quality。
- Claim 五类：`fact / calculation / interpretation / hypothesis / unknown`。
- **模板里不允许出现阿拉伯数字**：数字只能由 `{{m:...}}`、`{{f:...}}` 等 token 渲染，
  渲染时记录字符区间；区间外出现数字即 `CLAIM_UNBOUND_NUMBER` → BLOCK。
- 强断言词（必然/证实/造假/违约）BLOCK；一般因果词（导致/表明/意味着）WARN 转人工复核。
- 未过审的结论不进入正文，移入数据质量章节并保留原因与引用。

## 10. 版本、依赖与增量更新

### 10.1 依赖边

```
事实 key → 指标 → Claim → 章节 → 摘要
```

另设**集合哨兵**，用于捕获「以前不存在的新事实」：

- `coverage:{entity}:{year}:{field}`：即使该字段当前没有事实，也先登记；
- `peer_set:{entity}:{year}:{metric}`：同业集合成员变化；
- `topic:industry:{industry}:{period}`：行业统计新增年度。

### 10.2 增量流程

```
changed  = diff(old_resolutions, new_resolutions) + 新增事实键
impacted = downstream_bfs(union(old_deps, new_deps), changed)
recompute affected metrics / peer groups → rerun rules & claims
copy untouched section_version_ids → 只重新渲染命中章节
validate all refs → 生成 old/new/diff/recompute 计划
commit: CAS 更新 head；基线过期 → 409 STALE_BASE；无语义变更 → NO_CHANGE
```

### 10.3 实测（v1 → 补证 v2）

| 项 | 结果 |
|---|---|
| 变化事实 | 2 条（营业成本、啤酒业务成本） |
| 变化指标 | 2 条（毛利率 41.36% → 42.39%，变动 −2.57pp → −1.54pp） |
| 预测受影响 | 6 个（overview / operations / financials / peer / risk / data_quality） |
| 实际改写 | 6 个，与预测**完全一致**（无误判、无遗漏） |
| 未变章节 | 2 个（industry / chain），**沿用同一 `section_version_id` 与 hash** |
| 规则变化 | margin_pressure 由 TRIGGERED 回落 NOT_TRIGGERED |
| 旧版本 | 完整可读，hash 未被覆盖 |

## 12. 评测方法与结果

### 12.1 方法：两条互不替代的赛道

| 赛道 | 输入 | 参照 | 用途 |
|---|---|---|---|
| **跨源互证**（主口径） | 巨潮年报原件抽取结果 | 东方财富结构化数据 | 对外称「精度」 |
| 模板回归（辅助） | 合成年报 PDF | 生成方金标 | 只防抽取器退化 |

主口径不设自建金标：参照值是另一家机构独立录入的结构化数据，
两边同时错才会造成「假一致」，因此比自建金标可信。

判定规则写死在 `app/eval/crosscheck.py`：相差 0 记 `exact`，≤1 元记 `rounding`，
整千/整万倍记 `unit`（单位换算错，不算一致），其余 `mismatch`。

### 12.2 结果（2026-11-21，本机实测）

样本：6 行业 × 3 家公司 × 3 个财年 × 9 个字段，共 54 份年报原件、1,015 条抽取事实。

| 指标 | 实测 | 说明 |
|---|---|---|
| 可比值 | **384** | 两边都有值才计入 |
| 跨源一致率 | **84.1%**（323/384） | 不是 100%，也不应声称 100% |
| 真不一致 | **61** | 逐条列出公司、字段、页码与两边数值 |
| 跨年重述 | **45** | 同一指标在两份年报中数值不同 |
| 引用可达 | **100%** | 每条引用可打开文档 / 公式 / 定位 |
| 内部复算一致 | **108/108** | `Fraction` 另写公式；属内部一致性，非外部准确率 |
| 增量隔离 | **通过** | 预测受影响章节 = 实际改写章节；未命中章节保持同一 `section_version_id` |
| 缺证误显示为 0 | **0 条** | 缺证只显示缺口 |

按字段一致率：负债合计 92.7%、资产总计 91.1%、应收账款 90.5%、归母净利润 88.6%、
经营现金流 84.3%、营业收入 79.3%、营业成本 74.5%、存货 69.7%。

失败归因（详见 `docs/评测口径.md`）：列错位（母公司列被当合并）、年份错位、
行混淆（补充资料同名行）、标签拆行、口径差异（营业总收入 vs 营业收入）。

### 12.3 局限（必须说明）

1. **参照值也可能错**。第三方数据存在录入错误与口径调整，「不一致」不等于「我方错」，
   每条 `mismatch` 都附页码，需人工确认。
2. **只覆盖 6 个行业、9 个字段**。金融业（银行/保险）报表结构不同，未纳入。
3. **只处理有文本层的 PDF**。扫描件标 `SCANNED_UNSUPPORTED`，不做 OCR。
4. **抽取器在真实年报上仍有约 16% 的不一致**，失败样本已分类列出，不做删改或美化。
5. **答疑为「规则 + 模板 + 检索」**，大模型通道已留接口（`providers/llm.py`），
   接入后需重新验证「不越出版本证据」与「不写数字」两条约束。
6. **样本合计不等于行业总量**，报告一律标注「样本口径（n=3）」。

| 扫描件 OCR | 不做 | 无文本层标 `SCANNED_UNSUPPORTED`，允许人工录入候选并附原页 |
| 任意用户上传 | 不做 | 只处理预置语料 + 受控候选，避免不可信文件解析 |
| Neo4j / 向量库 | 不做 | 产业链是 8–15 节点的结构化边表；检索用 SQLite FTS5 |
| 多行业自动扩展 | 已做 6 个行业 | 新增行业需补 `config/chains/*.yaml` 与字段别名 |
| 实时行情 / 信用评分 | 不做 | 输出观察线索，不输出投资或授信结论 |
| 鉴权与多租户 | 不做 | 仅监听 127.0.0.1；银行上线需 SSO、最小权限、审计留存、内外网隔离 |
| 进程重启无感恢复 | 不做 | stale running 标 interrupted，重试建新 run 并复用可验证工件 |

已知风险：① 真实年报版式差异大，仍有约 16% 的跨源不一致；
② 单进程架构不适合并发多用户；③ 答疑若接大模型，需重新验证「不越出版本证据」。
